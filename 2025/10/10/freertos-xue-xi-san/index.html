延时函数

API

函数名 功能 备注
vTaskDelay 相对延时
vTaskDelayUntil 绝对延时 可设置周期性任务

vTaskDelay

FreeRTOSConfig.h中的INCLUDE_vTaskDelay必须设置为1，才能使用vTaskDelay() API函数。

函数原型

概述
  • vTaskDelay() 函数用于将调用该函数的任务置于 阻塞态（Blocked state），持续指定数量的 系统节拍中断（tick interrupts）。
  • 如果延时时间参数为 0 个节拍，任务不会进入阻塞态，而是直接让出（yield）处理器使用权给处于就绪态（Ready state）且具有相同优先级的其他任务。因此，调用 vTaskDelay(0) 的效果等同于调用 taskYIELD()。
参数
参数 说明
xTicksToDelay 保持在阻塞态的节拍数
  • xTicksToDelay：
    • 指定任务在被转换回就绪态（Ready state）之前保持在阻塞态的节拍数。例如：若当前系统节拍计数值为 10,000，任务调用 vTaskDelay(100)，则该任务会立即进入阻塞态，并保持阻塞直至系统节拍计数达到 10,100。
    • 在调用 vTaskDelay() 到下一个节拍中断到来之间的任何时间，都将被视为一个完整的节拍周期。因此，指定延时时间的最大时间分辨率，在最坏情况下等于一个完整的系统节拍中断周期。例如：

      t = 100.3 ms，任务调用 vTaskDelay(1)。此时当前 tick 计数为 100。系统记录：需要延时 1 tick，即直到 tick 计数到达 101。t = 100.3 ms ~ 101 ms，任务立即进入 Blocked（阻塞态）。虽然此时距离下一次 tick 中断还有 0.7 ms，但这段时间也被算作“一个完整 tick 周期”。t = 101 ms（下一次 tick 中断到来），tick 计数增加到 101。延时完成，任务从 Blocked → Ready 状态转移，等待调度器再次分配 CPU。
    • 宏定义 pdMS_TO_TICKS() 可用于将 毫秒（ms） 转换为 节拍数（ticks）。

vTaskDelayUntil

INCLUDE_vTaskDelayUntil必须在FreeRTOSConfig.h中设置为1，才能使用vTaskDelay() API函数。

函数原型

概述
  • vTaskDelayUntil() 函数用于将调用该函数的任务置于 阻塞态（Blocked state），直至系统时钟达到指定的 绝对时间（absolute time） 后才恢复执行。
  • 周期性任务（Periodic Tasks）可通过调用 vTaskDelayUntil() 来实现恒定的执行频率（constant execution frequency），从而保证任务以稳定的周期运行。
参数
参数 说明
pxPreviousWakeTime 保存任务上一次退出阻塞态（Blocked state）的系统时间
xTimeIncrement 设定任务的执行周期
  • pxPreviousWakeTime：
    • 该参数命名的前提是假设 vTaskDelayUntil() 被用于实现周期性任务（periodic task），即任务以固定频率循环执行。在这种情况下，pxPreviousWakeTime 用于保存任务上一次退出阻塞态（Blocked state）的系统时间（即任务被“唤醒”时的 tick 计数值）。该时间点被用作参考，用以计算任务下一次应当退出阻塞态的时刻。
    • 指针 pxPreviousWakeTime 所指向的变量会在 vTaskDelayUntil() 函数内部自动更新，因此在任务运行过程中无需用户手动修改，仅在变量首次初始化时需要由用户设定。
  • xTimeIncrement：
    • 该参数同样基于 vTaskDelayUntil() 用于实现周期性且固定频率执行任务的假设而命名。
    • 参数 xTimeIncrement 用于设定任务的执行周期（Execution Period），从而定义任务的固定执行频率。
    • xTimeIncrement 的单位为 系统节拍数（ticks）。
    • 宏定义 pdMS_TO_TICKS() 可用于将毫秒（ms）转换为节拍数（ticks），以便在编程时更直观地指定任务周期。

对比分析

系统节拍：

想要系统正常运行，那么时钟节拍是必不可少的，FreeRTOS的时钟节拍通常由SysTick提供，它周期性的产生定时中断，所谓的时钟节拍管理的核心就是这个定时中断的服务程序。FreeRTOS的时钟节拍isr中核心的工作就是调用vTaskIncrementTick()函数。

相对和绝对任务延时区别

调用vTaskDelay() 的任务进入 阻塞态（Blocked state），并保持阻塞指定数量的 系统节拍数（ticks）。任务退出阻塞态的时间是相对于调用 vTaskDelay() 的时刻（relative to when vTaskDelay() was called）来计算的。换言之，延时是相对延时（relative delay），即从调用函数开始计时。

同样，调用vTaskDelayUntil() 的任务进入 阻塞态（Blocked state），但其保持阻塞直至系统时钟达到指定的绝对时间（absolute time）。使用 vTaskDelayUntil() 的任务将在精确的目标时间点退出阻塞态，而非相对于函数调用时刻的延时。因此，vTaskDelayUntil() 实现的是绝对延时（absolute delay）机制，适用于固定周期执行的任务（periodic tasks），可确保任务周期恒定、执行频率稳定。
