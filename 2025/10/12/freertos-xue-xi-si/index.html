空闲任务（Idle Task）

FreeRTOS 是一个基于抢占或时间片轮转的多任务内核。它的运行逻辑大致是：

  • 内核维持若干个任务（Task Control Block, TCB）；
  • 调度器（Scheduler）每次从Ready 队列中选出优先级最高的任务；
  • 把 CPU 上下文切换到该任务，进入 Running；
  • 如果当前任务阻塞（Block）或挂起（Suspend），就从 Ready 列表移除；
  • 调度器再次选取新的 Ready 任务运行。

空闲任务在调度器启动时（vTaskStartScheduler()）自动创建，以确保始终至少有一个任务能够运行（至少有一个任务处于就绪状态）。

如果没有空闲任务：
所有任务若都处在挂起态或者阻塞态，那么就绪列表中没有可以进入运行态的任务，系统中没有任何任务可以运行。此时如果没有 Idle Task，调度器在选择“下一个任务”时将找不到任何可运行对象。
这会导致一些问题，比如：

  • 内核调度器进入死循环；
  • 系统停滞（硬件仍在运行，但没有上下文可切换）；
  • 某些版本下甚至可能触发断言或硬错误。

系统中必须至少存在一个能够进入 运行态（Running state） 的任务。为了确保这一点，当调用 vTaskStartScheduler() 时，调度器会自动创建一个 空闲任务（Idle Task）。空闲任务的主要功能只是循环执行一些简单操作。

//通用任务函数
void vTaskFunction( void *pvParameters )
{
    char *pcTaskName;
    const TickType_t xDelay250ms = pdMS_TO_TICKS( 250 );
    pcTaskName = ( char * ) pvParameters;
    /* As per most tasks, this task is implemented in an infinite loop. */
    while(1)
    {
        printf("%s", pcTaskName);
        vTaskDelay( xDelay250ms );   //进入阻塞态
    }
}
//任务创建
static const char *pcTextForTask1 = "Task 1 is running\r\n";
static const char *pcTextForTask2 = "Task 2 is running\r\n";
int main( void )
{
    //...
    xTaskCreate( vTaskFunction, "Task 1", 1000, (void*)pcTextForTask1, 1, NULL );
    xTaskCreate( vTaskFunction, "Task 2", 1000, (void*)pcTextForTask2, 2, NULL );  //高优先级

    /* Start the scheduler. */
    vTaskStartScheduler();   //空闲任务在此创建

    /* Will only get here if there was not enough heap space to create the
     * idle task. */
    return 0;
}

空闲任务的优先级最低（优先级为 0），以确保它不会阻止任何更高优先级的应用任务进入运行态。当然，应用程序设计者也可以创建与空闲任务相同优先级的任务，从而共享该优先级。

编译时配置常量 configIDLE_SHOULD_YIELD 定义于 FreeRTOSConfig.h 文件中，可用于控制空闲任务是否在合适时机主动让出 CPU 处理时间。若禁用该选项，空闲任务可能会消耗本可分配给其他应用任务的处理时间。

由于空闲任务运行在最低优先级，它会在任意更高优先级的任务进入 就绪态（Ready state） 时立刻被切出运行态。例如，在图 17 的时间点 tn 可观察到，当任务 2 解除阻塞（即离开 Blocked 状态）时，空闲任务立即被切出，使任务 2 得以执行。此时称任务 2 抢占（pre-empt） 了空闲任务。抢占过程完全自动进行，无需被抢占任务的参与或感知。

由于空闲任务负责在任务删除（此处指自杀任务，他杀任务由vTaskDelete()函数清理）后清理内核资源。若应用程序使用了vTaskDelete(xHandle)函数，则必须确保空闲任务不会被饿死（即不会长期得不到运行）。

空闲任务钩子函数（Idle Task Hook Functions）

可以通过空闲钩子函数（idle hook 或 idle callback）向空闲任务中添加用户自定义的功能。
空闲钩子函数会在空闲任务每次循环执行时自动被调用一次，从而允许用户在系统空闲时执行特定的应用逻辑。

函数原型：

//The idle task hook function name and prototype
void vApplicationIdleHook( void );

vApplicationIdleHook在FreeRTOS文件的位置：进入vTaskStartScheduler()，进入prvCreateIdleTasks()，找到下面这段代码，F12定位prvIdleTask

#if ( configNUMBER_OF_CORES == 1 )
       {
           pxIdleTaskFunction = &prvIdleTask;
       }

F12定位prvIdleTask找到函数portTASK_FUNCTION，内有如下代码

>#if ( configUSE_IDLE_HOOK == 1 )
>{
  /* Call the user defined function from within the idle task. */
  vApplicationIdleHook();
>}

钩子函数常见用途

在FreeRTOSConfig.h中，configUSE_IDLE_HOOK必须设置为1，空闲钩子函数才能被调用。

空闲任务钩子函数通常可用于以下场景：

  • 执行低优先级、后台或持续运行的处理功能。（例如周期性数据记录、诊断、系统状态监控等不会影响实时性的后台任务。）
  • 测量系统的空闲处理能力。（空闲任务仅在所有更高优先级的任务均无工作可执行时才会运行；因此，统计空闲任务所占的 CPU 时间即可清晰反映系统的空闲处理能力。）
  • 将处理器置于低功耗模式。这是一种在系统无任务执行时自动节能的简单方法。尽管通过这种方式实现的节能效果不如无时钟空闲模式（tick-less idle mode）显著，但仍能在无需复杂控制的情况下自动降低功耗。
    空闲任务钩子函数的实现限制（Limitations on the Implementation of Idle Task Hook Functions）

钩子函数的实现必须遵循以下规则：

空闲任务钩子函数在执行期间绝不能调用任何可能导致任务进入阻塞（Blocked）或挂起（Suspended）状态的 FreeRTOS API 函数。一旦空闲任务被阻塞，系统在无其他就绪任务时将无法调度到任何可运行任务，从而导致调度器停滞。

此外，当应用程序使用了 vTaskDelete() API 删除任务时，空闲任务还负责清理被删除任务所占用的内核资源。因此，空闲任务钩子函数必须在合理的时间内返回，以便空闲任务能周期性地执行资源回收操作。若钩子函数陷入无限循环或长时间占用 CPU，使空闲任务无法返回主循环，则任务删除后的资源将无法被及时释放，可能引发内存泄漏或系统异常。
