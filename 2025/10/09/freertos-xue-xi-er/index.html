任务创建

API

函数名 功能 动态/静态 备注
xTaskCreate 动态创建任务 动态
xTaskCreateStatic 静态创建任务 静态
xTaskCreateRestrictedStatic 静态创建受限任务(权限控制) 静态 很少用

xTaskCreate-动态创建任务

为使本函数可用，宏 configSUPPORT_DYNAMIC_ALLOCATION 必须在 FreeRTOSConfig.h 中设为 1，或保持未定义状态（默认启用动态内存分配）。

函数原型

概述
  • 创建一个新的任务实例。
  • 每个任务都需要一定的 RAM 空间，用于保存任务状态（即任务控制块，Task Control Block，简称 TCB）以及任务运行所需的栈空间。
  • 如果使用 xTaskCreate() 创建任务，则所需的 RAM 将自动从 FreeRTOS 的堆（heap）中分配。
  • 若使用 xTaskCreateStatic() 创建任务，则 RAM 由应用程序编写者自行提供。此时函数会多出两个额外的参数，用于传入静态分配的内存区域，以便在编译时即完成内存分配。
  • 新创建的任务初始状态为 Ready（就绪态），但如果当前没有更高优先级的任务可运行，则该任务会立即进入 Running（运行态）。
  • 任务既可以在调度器（scheduler）启动之前创建，也可以在调度器启动之后创建。
参数
参数 说明
pvTaskCode 指向任务函数的指针，用于指定任务所执行的函数体
pcName 任务的描述性名称，自定义
usStackDepth 任务所需的栈大小(由内核分配)
pvParameters 传递给任务函数的参数
uxPriority 定义任务的执行优先级
pxCreatedTask 用于输出所创建任务的句柄
  • pvTaskCode：
    • 任务本质上是一个不会退出的 C 函数，通常以无限循环的形式实现。
    • pvTaskCode 参数是指向该函数的指针（实质上就是函数名本身），用于指定任务所执行的函数体。
  • pcName：
    • 任务的描述性名称。该名称主要用于调试，也可以在调用 xTaskGetHandle() 时用于根据名称获取任务句柄。
    • 用户可在应用配置中通过常量 configMAX_TASK_NAME_LEN 定义任务名称的最大长度（以字符数计），该长度包含字符串结束符 NULL (‘\0’)。若提供的任务名称字符串长度超过此最大值，超出部分将被自动截断而不会产生警告。
  • usStackDepth：
    • 每个任务都有其独立的栈空间，该栈由内核在任务创建时分配。usStackDepth 参数用于告诉内核任务所需的栈大小。
    • 该参数的值表示栈可容纳的字（word）数量，而非字节数。例如，在字长为 4 字节的架构上，若 usStackDepth 传入 100，则实际分配的栈空间为 400 字节（100 × 4 字节）。栈深度与字长的乘积不得超过 size_t 类型所能表示的最大值。
    • 空闲任务（Idle Task）所使用的栈大小由应用定义常量 configMINIMAL_STACK_SIZE 指定。该常量在 FreeRTOS 提供的示例工程中为特定微控制器架构设置了推荐的最小栈深度。若任务执行过程中需要较多的栈空间，则应为 usStackDepth 分配更大的值。
  • pvParameters：
    • 任务函数可接收一个类型为 void*（指向任意类型的指针） 的参数。在创建任务时传入的 pvParameters 值将作为参数传递给任务函数。此参数采用 void* 类型，是为了允许任务以通用方式接收任意类型的数据。
    • 用户可在创建任务时将不同类型的数据通过强制类型转换为 void* 传入，在任务函数内部再将其转换回原始类型以使用。例如，可在创建任务时将一个整型变量转换为 void* 传入：
      xTaskCreate(TaskFunc, "TaskA", 200, (void*)myInt, 2, NULL);
      而在任务函数内部再将其还原为整型：
      int value = (int)pvParameters;
  • uxPriority：
    • 定义任务的执行优先级。值越小，优先级越低
    • 任务优先级的取值范围为 0（最低优先级）到 (configMAX_PRIORITIES – 1)（最高优先级）。configMAX_PRIORITIES 是用户自定义的常量。
    • 当 configUSE_PORT_OPTIMISED_TASK_SELECTION 设为 0 时，系统在理论上对可用优先级的数量没有上限（仅受数据类型与 MCU 可用 RAM 的限制）。然而，出于内存效率考虑，建议仅定义实际所需的最少数量的优先级，以避免浪费 RAM。
    • 若传入的 uxPriority 值超过 (configMAX_PRIORITIES – 1)，系统将自动将其截断至最大允许值，而不会产生错误提示。
  • pxCreatedTask
    • pxCreatedTask 用于输出所创建任务的句柄（task handle）。
    • 该句柄可在后续的 API 调用中用于引用该任务，例如：
      • 修改任务优先级；
      • 挂起或恢复任务；
      • 删除任务等。
    • 若应用程序不需要使用任务句柄，可将 pxCreatedTask 设为 NULL。
返回值
返回值 说明
pdPASS 表示任务已成功创建
errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY FreeRTOS 堆内存不足，任务创建失败
  • errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY：
    • 表示任务创建失败，原因是 FreeRTOS 堆内存不足，无法为任务的数据结构和栈分配所需空间。
    • 如果工程中包含 heap_1.c、heap_2.c 或 heap_4.c，则可用堆空间的总量由 FreeRTOSConfig.h 中的宏 configTOTAL_HEAP_SIZE 定义。当内存分配失败时，可通过 vApplicationMallocFailedHook() 回调函数（即“钩子函数”）捕获该错误。剩余可用堆空间的大小可通过 xPortGetFreeHeapSize() API 函数查询。
    • 若工程中使用 heap_3.c，则堆空间大小由链接器配置（linker configuration）决定。

xTaskCreateStatic-静态创建任务

要使该函数可用，必须在 FreeRTOSConfig.h 中将宏configSUPPORT_STATIC_ALLOCATION 设为 1。

函数原型

概述
  • 创建一个新的任务实例。
  • 如果使用 xTaskCreate() 创建任务，则所需的 RAM 将自动从 FreeRTOS 的堆（heap）中分配。
  • 若使用 xTaskCreateStatic() 创建任务，则 RAM 由应用程序编写者显式提供。此方式会在函数中增加两个额外的参数，但允许在编译阶段进行静态内存分配。
  • 手动提供任务栈和任务控制块（TCB），避免动态内存分配。
参数
参数 说明
pvTaskCode 指向任务函数的指针，用于指定任务所执行的函数体
pcName 任务的描述性名称，自定义
ulStackDepth 任务栈大小（以字为单位）
pvParameters 传递给任务函数的参数
uxPriority 定义任务的执行优先级
puxStackBuffer 指向任务栈缓冲区的指针（由用户提供）
pxTaskBuffer 指向任务控制块的缓冲区（由用户提供）
  • puxStackBuffer：
    • 参数用于向 xTaskCreateStatic() 传递一个 StackType_t 类型数组。ulStackDepth 必须被设置为该数组中元素（索引）的数量。
    • 换言之，ulStackDepth 定义了任务栈的深度（以“字”为单位），而 puxStackBuffer 则提供了实际的静态栈空间。
  • puxStackBuffer：
    • 必须指向一个 StackType_t 类型数组，该数组的长度至少应包含 ulStackDepth 个元素（参见上文的 ulStackDepth 参数说明）。
    • 该数组将被用作所创建任务的栈空间（stack），因此必须是持久存在(persistent)的内存区域。换言之，不能在函数的栈帧（stack frame）中声明该数组，也不能使用在程序执行过程中可能被合法覆盖的其他内存区域。
  • pxTaskBuffer：
    • 必须指向一个 StaticTask_t 类型的变量。
    • 该变量将用于保存任务的数据结构（TCB，Task Control Block），因此同样必须是持久存在的内存区域。同样地，pxTaskBuffer 不能定义在函数栈帧内部，也不能位于任何在程序运行过程中可能被系统或用户逻辑覆盖的内存空间中。
返回值
返回值 说明
NULL 任务创建失败
任意非 NULL 值 任务已成功创建，返回值即为该任务的任务句柄
  • NULL：任务创建失败。原因是 puxStackBuffer 或 pxTaskBuffer 为 NULL。
  • 任意非 NULL 值：若返回值为非 NULL，则任务已成功创建，返回值即为该任务的任务句柄（Task Handle）。

任务删除

vTaskDelete()

函数原型

概述

  • 删除一个通过 xTaskCreate() 或 xTaskCreateStatic() 创建的任务实例。
  • 被删除的任务不再存在，因此无法进入 Running（运行）状态。
  • 请勿尝试使用任务句柄（task handle）去引用已经被删除的任务。
  • 当一个任务被删除时，空闲任务（idle task） 负责释放该任务所占用的内存资源，包括任务栈（stack）和任务控制块（Task Control Block，TCB）。因此，当应用程序调用 vTaskDelete() API 函数时，必须确保空闲任务有足够的处理时间（即空闲任务必须被调度执行），否则无法完成这些内存的释放操作。
  • 仅由 内核（kernel） 为任务分配的内存会在任务被删除时自动释放。而任何由用户自行分配与任务相关的内存或资源（如动态分配的缓冲区等），必须在任务删除时由用户显式释放。

参数

参数 说明
pxTask 任务句柄
  • pxTask：
    • 表示被删除任务的句柄（即目标任务）。
    • 若要获取任务句柄，可在调用 xTaskCreate() 创建任务时，使用其参数 pxCreatedTask；或者使用 xTaskCreateStatic() 创建任务并保存其返回值；也可以通过任务名称调用 xTaskGetHandle() 来获取对应的任务句柄。
    • 任务也可以自我删除，此时在 vTaskDelete() 的参数中传入 NULL 即可（即用 NULL 代替有效的任务句柄）。
